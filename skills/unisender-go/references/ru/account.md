# Аккаунт, проекты и отправитель

[English](../account.md) | [Русский](account.md)

Источники: [system](https://godocs.unisender.ru/web-api-ref#system), [domain](https://godocs.unisender.ru/web-api-ref#domain), [project](https://godocs.unisender.ru/web-api-ref#project), [confirmed-email](https://godocs.unisender.ru/web-api-ref#confirmed-email). Проверено 2026-10-26.

## Подключение

`system/ping` с `{}` проверяет ключ и возвращает `user_id`. `system/info` с `{}` дополнительно показывает область и лимиты:

- `project_id`, `project_name`, `project_accounting` — ключ проекта;
- `accounting` с периодом и `emails_included`/`emails_sent` — ключ пользователя.

Используй ключ подходящего проекта. Не переключайся на другой проект самостоятельно из-за отказа в доступе. Управление проектами, sandbox и confirmed-email требуют ключа основного аккаунта; проектный ключ не заменяет его. Возможности аккаунта всё равно могут ограничивать методы проектов и возвращать 403 — сообщай фактическую ошибку. Нулевое значение в счётчиках само по себе не определяет тариф или доступный объём отправки.

## Существующий домен

Начни с `domain/list`, тело `{"domain":"example.com"}`. Для готовности отправителя нужны:

- `domains[].verification-record.status` = `confirmed`;
- `domains[].dkim.status` = `active`.

Само наличие домена или успешный вызов проверки этого не доказывают.

## Подготовить новый домен

1. `domain/get-dns-records` с `{"domain":"example.com"}` возвращает записи и **регистрирует домен/генерирует ключи**, если их ещё нет. Поэтому требуется `--execute` в рамках поручения настроить этот домен.
2. Значение `verification-record` публикуется TXT на корне домена. DKIM — TXT `us._domainkey`, содержимое `k=rsa; p=` плюс возвращённое поле `dkim` (это публичный ключ, не API-ключ).
3. Рекомендуемая SPF-механика: `include:spf.unisender.ru/go`. Если SPF уже существует, добавь механизм в существующую запись, сохранив её смысл; не создавай вторую SPF-запись и не заменяй действующую целиком.
4. После публикации DNS запусти `domain/validate-verification-record` и `domain/validate-dkim` с тем же JSON и `--execute`. Успешный ответ означает **запуск** проверки.
5. Позже прочитай `domain/list` и проверь оба финальных статуса. При задержках DNS сообщи текущие состояния, не запускай бесконечные повторные проверки.

Клиент Go не редактирует DNS у регистратора. Если пользователь просит показать записи — покажи их; изменение DNS требует отдельного инструмента и соответствующего поручения.

## Sandbox и подтверждённые адреса

`domain/get-sandbox-domain` с `{}` возвращает существующий sandbox или **создаёт** новый, поэтому это операция `write`, доступная с `--execute`.

`confirmed-email/list` с `{}` показывает подтверждённые и неподтверждённые адреса. `confirmed-email/create` с `{"email":"..."}` **отправляет ссылку подтверждения**; это реальное письмо, а не локальная проверка адреса. Создание записи не подтверждает владение: получатель должен перейти по ссылке. Затем проверь статус через `confirmed-email/list`. `confirmed-email/delete` удаляет адрес. У обоих изменяющих методов нужен `--execute`. На бесплатном тарифе отправка внешним адресатам может возвращать ошибку 903: может потребоваться подтверждение адреса или подходящий платный тариф. Sandbox не отменяет ограничения тарифа/доступных адресатов: сверяй конкретную ошибку API и условия аккаунта.

## Проекты

| Метод | Тело |
|---|---|
| `project/list` | `{}` или `{"project_id":"..."}` |
| `project/create` | `{"project":{"name":"Transactional app"}}` |
| `project/update` | `{"project_id":"...","project":{"name":"Existing name","send_enabled":true}}` |
| `project/delete` | `{"project_id":"..."}` |

Для выбора проекта используй `project_id`, а не ключ проекта в JSON-файле. `project/list` возвращает `projects[].api_key`, а создание — `project_api_key`: клиент скрывает оба. Для получения нового ключа пользователем используй кабинет или его менеджер секретов; клиент намеренно не сохраняет сырой ответ с ключом.

В обновлении требуется `project.name`; сначала прочитай текущие свойства и сохрани нужное имя. Не обнуляй `email_counter`, не снимай `email_counter_limit`, не отключай ссылки отписки по умолчанию. Удаление проекта/домена выполняй только для конкретно указанного объекта в рамках явного запроса.
