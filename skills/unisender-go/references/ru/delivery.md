# Доставка и статистика

[English](../delivery.md) | [Русский](delivery.md)

Источники: [event-dump/create](https://godocs.unisender.ru/web-api-ref#event-dump-create), [event-dump/get](https://godocs.unisender.ru/web-api-ref#event-dump-get), [callback-format](https://godocs.unisender.ru/web-api-ref#callback-format). Проверено 2026-10-26.

В Go нет `getCampaignStatus` из маркетингового API. Используй вебхуки или асинхронный `event-dump`.

## Выгрузка событий по заданию

Уточни период, если он не следует из задачи. Времена API — **UTC**, строки `YYYY-MM-DD HH:MM:SS`; верхняя граница `end_time` не включается. Переводи «вчера» из часового пояса пользователя, а не из системного UTC. Например, сутки 25 октября 2026 в Москве — от `2026-10-24 21:00:00` до `2026-10-25 21:00:00` UTC.

```json
{
  "start_time": "2026-10-24 21:00:00",
  "end_time": "2026-10-25 21:00:00",
  "limit": 100000,
  "filter": {"job_id": "REPLACE_WITH_JOB_ID"},
  "format": "csv"
}
```

1. Сохрани JSON и вызови `event-dump/create --data-file events.json --execute`. Подготовка выгрузки является записью, но запрос пользователя «выгрузи события» разрешает эту подготовку.
2. Возьми `dump_id` из ответа и вызови `event-dump/get` с `{"dump_id":"..."}`.
3. Состояние находится в **`event_dump.dump_status`**: `queued`, `in_process`, `ready`, `failed`. Не путай его с верхнеуровневым `status: success`.
4. Проверяй с паузами, например 5–10 секунд, ограничив ожидание двумя минутами за один запуск задачи. Если ещё не готово, верни `dump_id` и состояние. Не создавай повторный дамп вместо ожидания.
5. Ссылки на CSV/CSV.GZ находятся в **`event_dump.files[].url`**. Файлов может быть несколько; обработай все. Частичные файлы доступны и во время `in_process`, но не называй их полным результатом.

Полная команда создания выгрузки из каталога скилла:

```bash
python3 scripts/unisender_go.py call event-dump/create --data-file events.json --execute
```

Клиент не скачивает файлы автоматически. Для анализа скачивай только HTTPS-ссылки из ответа на этот запрос, не добавляя к ним `X-API-KEY` и не передавая ключ в query. Сохраняй данные в рабочем каталоге, не в самом скилле. Ссылки на выгрузки могут давать доступ к данным; не публикуй их без необходимости.

По умолчанию API возвращает только **50 событий**: всегда выбирай явный `limit` под задачу. Достижение лимита может означать усечение. Не утверждай полноту без проверки; при необходимости разбей период на более короткие интервалы. Каждый файл содержит максимум 100 000 событий. Данные доступны до 45 дней в зависимости от тарифа; одновременно хранятся/создаются максимум десять дампов, срок хранения готового дампа — восемь часов. Не удаляй чужие/старые дампы только для освобождения слота без соответствующего разрешения.

Для списка существующих дампов: `event-dump/list`, тело `{}`. Удаление: `event-dump/delete`, тело `{"dump_id":"..."}`, с `--execute`.

## Агрегаты и трактовка

Для общей статистики по дням можно задать `aggregate: "day_status"`. С этим режимом **нельзя передавать непустой `filter`**, в том числе `job_id`. Для отдельного задания выгружай события с фильтром и считай показатели локально. Поле выбора колонок — `dump_fields`, несмотря на опечатку `dump_fileds` в одном абзаце документации.

Различай `accepted`, `sent`, `delivered`, `opened`, `clicked`, `soft_bounced`, `hard_bounced`, `unsubscribed`, `subscribed`, `spam`. `soft_bounced` допускает дальнейшие попытки доставки; `hard_bounced` — окончательная недоставка.

При подсчёте уникальных писем учитывай пару `(job_id, email)`: один `job_id` может охватывать несколько адресатов, а одно письмо может породить несколько событий. Определи и назови знаменатель для open rate/CTR, период, область аккаунта/проекта и полноту выборки. Не складывай открытия, клики и доставки как независимые отправления. Событие открытия отражает зарегистрированное отслеживание, а не гарантированное прочтение человеком.
